# Warudo 非角色类 Mod：打包与脚本规范

本文只讲**除角色 Mod 之外**的 Mod：道具/粒子/环境（资源型）与插件（蓝图节点型）。
环境：Warudo 0.15.0 + Warudo Mod Tool 0.14.4.8 + Unity 2021.3.45f2。

## 1. 先分清三条"构建"路径

| 你要做的 | 路径 | 产物 | 需要 Unity | 需要 C# |
|---|---|---|---|---|
| 一张蓝图 | 编辑器画 → `Export blueprint to file` | `.json` | ❌ | ❌ |
| 道具 / 粒子 / 环境 / 动画 | Unity + SDK → `Warudo → Build Mod` | `.warudo` | ✅ | 可选 |
| **给蓝图加新节点** | Unity + SDK → `Warudo → Export Mod`（插件 Mod） | `.warudo` | ✅ | **必须** |

**关键结论：往节点面板加节点的唯一途径是"插件 Mod"，下限就是本仓库 `Mods/HoTestPlugin` 那样
两个 `.cs` 文件。** 纯蓝图只能"用节点"，不能"造节点"。

## 2. Mod 工作区（modAssetPath）的硬性约定

Mod 工作区就是一个普通文件夹，**所有资源与脚本都必须放在里面**，放外面不会被打包。

| 类型 | 根对象 | 必须命名 | 落点（Warudo 数据目录） |
|---|---|---|---|
| 道具 Prop | Prefab | **`Prop`** | `StreamingAssets/Props` |
| 粒子 Particle | Prefab | **`Particle`** | `StreamingAssets/Particles` |
| 环境 Environment | Scene | **`Environment`**（+ 场景内挂 `EnvironmentSettings`） | `StreamingAssets/Environments` |
| 角色动画 | AnimationClip | **`Animation`** | `StreamingAssets/CharacterAnimations` |
| **插件 Plugin** | 无根资产要求 | 只要工作区里有继承 `Plugin` 的 C# 类 | `StreamingAssets/Plugins` |
| 角色 Character | Prefab | **`Character`** | `StreamingAssets/Characters` |

推荐布局（本仓库就是这么放的）：

```
<ModName>/                      ← modAssetPath 指向这里
  <ModName>Plugin.cs            // 插件入口 [PluginType]
  Nodes/<Xxx>Node.cs            // 自定义节点
  Nodes/<Sub>/<Yyy>Node.cs      // 节点也可以放子目录
  Assets/<Xxx>Asset.cs          // 自定义 Asset（如果注册了 AssetTypes）
  Behaviors/<Xxx>Behavior.cs    // MonoBehaviour
  Localizations/Warudo.<ModName>.json
```

## 3. 插件 Mod 的最小骨架

```csharp
[PluginType(
    Id = "yourname.plugin",            // 不要求是 GUID，但要求全局唯一
    Name = "Your Plugin",
    Description = "...",
    Version = "1.0.0",
    Author = "you",
    NodeTypes = new[] { typeof(MyNode) })]   // 漏写就不会出现在节点面板
public class YourPlugin : Plugin { }
```

节点：

```csharp
[NodeType(Id = "<GUID>", Title = "My Node", Category = "YourCategory")]
public class MyNode : Node {
    [DataInput]  public float A = 1f;                       // 数据输入 = public 字段
    [DataOutput] public float Result() => A * 2f;           // 数据输出 = public 方法
    [FlowInput]  public Continuation Enter() { return Exit; } // 流程输入 = 返回 Continuation
    [FlowOutput] public Continuation Exit;                  // 流程输出 = Continuation 字段
}
```

规则：

* `[NodeType].Id` 官方要求 **每个新节点生成一个新 GUID**（是规范不是强校验；
  但类型 Id 是跨 Mod 寻址主键，用 GUID 可以避免撞名）。
* `[PluginType].Id` 社区惯例是 `author.modname` 这种反向域名式，不用 GUID。
* 一个流程输入可以接多个流程输出；一个流程输出只能接一个流程输入。
* 数据端口同理：一个数据输出可连多个数据输入，一个数据输入只能连一个数据输出。
* `Continuation` 三态：`return Exit;`（继续走）/ `return null;`（流程终止）/ `InvokeFlow(nameof(Exit))`（延迟或手动触发）。

### 3.1 两个实测踩到的编译坑

这两条都是本仓库在**对着真机 Warudo DLL 编译**时抓出来的，写节点时几乎必然会遇到：

1. **命名空间不要起成 `...Plugin`。**

   ```csharp
   namespace HoWarudoModTests.Plugin {   // ✗
       public class HoTestPlugin : Plugin { }   // CS0118
   }
   ```

   `using Warudo.Core.Plugins;` 引入的 `Plugin` 基类会被**自己所在的命名空间**
   `HoWarudoModTests.Plugin` 遮蔽，报
   `CS0118: "Plugin" 是命名空间，但此处被当做类型来使用`。
   解决办法：命名空间换成 `...PluginMod`，或者把基类写成全限定名
   `Warudo.Core.Plugins.Plugin`。

2. **`[DataInput]` 字段名不要撞 `Node` 基类成员。**

   ```csharp
   [DataInput] public string Name = "World";   // CS0108
   ```

   `Node` 基类已经有 `Name` 成员，会报
   `CS0108: xxx.Name 隐藏继承的成员 Node.Name`。
   虽然只是警告，但它意味着你**遮蔽了基类字段**，节点在面板里显示的名字等行为会变得不可预期。
   数据输入请取业务名（本仓库用 `Who`）。

> 这两类错误不需要启动 Unity 就能发现：本仓库 `tools/compile-check.ps1` 用 Roslyn
> 直接对着 `Warudo_Data/Managed` 下的真机 DLL 编译一遍，秒级出结果。

## 4. 多文件 / 多目录脚本怎么才能正确打包

这是最容易踩坑的地方。实测规则：

1. **UMod 不是"扫描 Mod 目录里的 `.cs`"，而是读 Unity 生成的 `.csproj`** 里的
   `<Compile Include="Assets\...">` 列表来决定编译哪些源码
   （`ScriptCompiler.Project.ProjectLocator`）。

   → 后果：工程根目录没有 `.csproj` 时，构建**会报成功**，但一个脚本都没编译，
   产物里没有 `assemblymodules.dat`，组件在 Warudo 里全是 Missing Script。
   → 修法：`Edit > Preferences > External Tools` 选好编辑器 → `Regenerate project files`，
   确认工程根目录出现 `Assembly-CSharp.csproj`。

2. **只要在 Mod 工作区内、能被 Unity 导入的 `.cs`，都会被编译进 Mod 程序集**，
   与"是否被组件引用"无关`。本仓库用 `HoTestPropUtils.cs`（无任何引用）和
   `Internal/HoTestPropInternal.cs`（子目录）专门验证这一点。

3. **子目录随便嵌套**，没有额外的目录约定（不像 Unity 需要 asmdef）。

4. **不要加 `.asmdef`**：被 asmdef 覆盖的脚本不会被打包进 Mod。

5. **不要放已编译的 DLL**：插件 Mod 只能带 `.cs` 源码，第三方 DLL/NuGet 不支持。

6. **工作区路径不能是 `Assets` 根目录**，也不能放在 Unity 忽略的目录里
   （如以 `~` 结尾或以 `.` 开头的目录），否则 Prefab 无法可靠导入和链接。

7. 同一份源码不要同时出现在多个 Mod 工作区里，否则类型重复。

### 判断"脚本到底进没进包"

产物 `.warudo` 是 **12 字节 `UMOD` 头 + 标准 ZIP**：

```
modinfo.dat          必须有（UMod 自己的二进制元数据，内嵌缩略图 PNG）
sharedassets.bin/meta  资源包（资源型 Mod）
sceneassets.bin/meta   场景资源包（环境型 Mod）
assemblymodules.dat    编译后的托管程序集 —— 只有带 C# 的 Mod 才有
```

所以：**看到 `assemblymodules.dat` 才说明脚本真的被编进了包。**
它的内容是一个或多个 PE 镜像，程序集名形如 `umod-compiled-<GUID>`。

> `.modinfo.dat` 不是 JSON。它里面能读出打包时用的 SDK 版本、Unity 版本、
> Warudo Mod Tool 版本、Mod 名/版本/描述/作者 —— 排查兼容性时很有用。

## 5. 构建入口（官方 API）

菜单 `Warudo → Build Mod`（快捷键 `Ctrl+Shift+B`）背后的代码就是：

```csharp
var settings = UMod.ModTools.Export.ExportSettings.Active;   // 载入 ExportSettings 资源
UMod.BuildEngine.ModToolsUtil.StartBuild(settings);          // 同步返回 ModBuildResult
```

`StartBuild` 的完整签名（0.14.4.8 实测）：

```csharp
UMod.BuildEngine.ModBuildResult StartBuild(UMod.ModTools.Export.ExportSettings, System.Action)
```

返回值 `ModBuildResult` 上有：`Successful`、`BuiltModFile`、`BuildTime`、`ErrorMessage`。

其它可用入口：

```csharp
UMod.BuildEngine.ModToolsUtil.ShowToolsWindow(typeof(UMod.Exporter.CreateModWindow));   // New Mod
UMod.BuildEngine.ModToolsUtil.ShowToolsWindow(typeof(UMod.Exporter.ExporterWindow));    // Switch Active Mod
UMod.BuildEngine.ModToolsUtil.ShowToolsWindow(typeof(UMod.Exporter.SettingsWindow));    // Mod Settings
UMod.BuildEngine.ModToolsUtil.StartBuildAndRun(settings, null);
UMod.BuildEngine.ReferenceAssemblyLoader.LoadReferencedAssemblies(false);
```

### Export Profile（= ExportSettings.asset 里的 `exportProfiles[]`）

构建配置是一个 Unity ScriptableObject，一个工作区一项：

```yaml
exportProfiles:
- referencePaths: []
  modName: HoTestProp
  modAuthor: Hollow
  modVersion: 1.0.0
  modDescription: ...
  modAssetPath: D:/Unity_Project/BreakWarudo/Assets/HoWarudoModTests/Mods/HoTestProp
  modExportPath: D:/.../StreamingAssets/Props
  modIcon: {fileID: 0}
```

对应 API：`ExportSettings.ExportProfiles` / `ActiveExportProfile` / `ActiveExportProfileIndex` /
`SetActiveExportProfile` / `CreateNewExportProfile(bool)` / `DeleteExportProfile` /
`RemoveDuplicateProfiles` / `ValidateName` / `ValidateAssetPath` / `ValidateVersion`；
单项字段在 `ExportProfileSettings` 上（`ModName` / `ModAssetsPath` / `ModExportPath` / …）。

⚠️ `modAssetPath` 与 `modExportPath` 官方窗口里显示的是**绝对路径**。

> 这个资源文件很容易被 UMod 擦写（脚本变化、Unity 重获焦点时可能被清空）。
> 建议连同工程一起做版本管理/备份。

## 6. 运行时限制（UMod 安全审查）

编译后会做 API 引用审查，命中即构建失败：

* 禁用命名空间：`System.IO.*`、`System.Reflection`、`System.Reflection.Emit`、
  `System.Runtime.InteropServices`、`UnityEditor`、`Mono.Cecil`、`UMod-ModTools` 等
* 禁用类型：`System.AppDomain`、`System.Diagnostics.Process`、`System.Threading.Process`
* **P/Invoke 全局禁用**
* 不支持：`.asmdef`、ScriptableObject、已编译 DLL、第三方 NuGet

替代方案：文件读写用官方沙箱化 IO API；需要跨对象调用时用 Unity 的
`SendMessage` / `BroadcastMessage`，或官方的 `PluginRouter`（signals / commands）。

> 注意 `exception.GetType().Name` 也会被拒 —— 编译后 IL 里是 `MemberInfo.Name`。
> 运行时错误提示请用固定文本 + `Debug.LogException(exception)`。

## 7. 渲染管线：Warudo 是 BiRP

**Warudo 用的是 Built-in Render Pipeline（BiRP），Warudo Pro 才提供 URP 选项。**

* 道具/粒子的材质请用内置的 `Standard` 等 BiRP 着色器；
  用 `Universal Render Pipeline/Lit` 做出来的 Mod 进 Warudo 会丢材质/变粉。
* 自定义 shader 按 BiRP 写；URP 下的自定义 shader 支持面要窄得多
  （官方只保证内置 URP shader + NiloToon + PotaToon）。
* Warudo SDK 包里对 URP 包的依赖，是 SDK 自身支持 URP 用的，**不代表你的 Mod 要按 URP 做**。

## 8. 上传创意工坊

在 Warudo 应用内：`Discover → Published Items → Create Item`，表单字段：

| 字段 | 说明 |
|---|---|
| `Title` / `Description` | 标题与简介 |
| `Tag` | 分类。工坊只有 5 类：`Characters` / `Environments` / `Props` / `Plugins` / `Miscellaneous` |
| `Files` | 要上传的文件，例如 `Props/HoTestProp.warudo`（用 `+` 添加） |
| `Preview Image` | 预览图，**必须小于 1 MB**，从数据目录的 `Images` 取 |
| `Visibility` | `Public` |

⚠️ 工坊**没有** `Character Animations`、`Particles`、`Blueprints` 分类 ——
这几类实际上被打成 `Miscellaneous`。

依赖关系不要用 uMod 的 reference dependency，用 Warudo 0.14.3+ 的 `PluginRouter`。
用 SDK ≥ 0.14.5.1 构建的 Mod 只能在 Warudo ≥ 0.14.5 载入。

## 9. 构建前检查清单

0. **先跑 `tools/compile-check.ps1`**（秒级、不用开 Unity），确认脚本能对着真机 DLL 编译通过
1. Warudo Mod SDK 已导入，`Warudo` 菜单存在
2. Player Settings：**Api Compatibility Level = .NET Framework**、
   **Assembly Version Validation 取消勾选**
3. Unity 版本与 SDK 匹配（Mod Tool 0.14.5.1 → Unity 2021.3.45f2）
4. 工程根目录有 Unity 生成的 `.csproj`
5. Mod 工作区在 `Assets` 下、不是 `Assets` 根目录、不在 Unity 忽略目录里
6. 根对象按类型命名正确（`Prop` / `Particle` / `Environment` / `Animation`）
7. 插件 Mod：`[PluginType].NodeTypes` 列全了所有节点
8. 导出前关闭 Warudo，清掉 `StreamingAssets/Playground` 下的同名脚本
9. 构建后检查产物里有没有 `assemblymodules.dat`（有脚本时）
